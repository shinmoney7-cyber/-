# 다국영상 하이라이트 클립 제작 스킬

> 목적: 해외 원본 영상 속 등장인물들의 대화를 한국어로 자연스럽게 번역하고,
> 하이라이트 구간은 클로즈업·비교 연출을 더해 "재미"를 극대화한 대본 톤으로 재구성해
> 저작권 리스크를 관리하면서 유튜브 등에 업로드 가능한 형태로 만든다.
> (뉴스 보도체가 아니라, 예능/리액션 콘텐츠에 가까운 톤을 기본으로 한다.)

## 입력

- 원본 영상 URL 또는 파일 1개 이상
- 벤치마킹할 레퍼런스 채널/영상 (선택) — 제목·자막 톤을 참고할 대상. **사용자가 실제 링크나 캡처를 제공해야 그 스타일을 분석한다. 채널명만 듣고 임의로 "이 채널은 이런 스타일이다"라고 단정하지 않는다.**
- 타깃 언어 (자막/더빙 출력 언어, 예: 한국어 위주 + 영어 병기)

## 사용 도구 + 설치

- 검색: `WebSearch` (Claude 내장 도구)
- 대사 받아쓰기(STT): 원본에 자막이 있으면 자막 파일을 우선 사용. 없으면 Whisper — `pip install openai-whisper` 후 `whisper <파일> --language <원문 언어> --output_format srt`
- 프레임 추출: `ffmpeg` — 맥 `brew install ffmpeg` / 리눅스 `sudo apt-get install -y ffmpeg`
- 썸네일 보조 이미지: Higgsfield MCP `generate_image` (deferred면 ToolSearch로 로드, 없으면 claude.ai 설정 > 커넥터에서 연결)
- 조립: CapCut (사용자 PC에 설치, capcut.com)

## 진행 체크리스트

- [ ] 0. 소재 후보 5개 — 몇 개 만들지 확인받기
- [ ] 1. 원본 확보 + 사실관계 정리
- [ ] 2. 하이라이트 구간 3~5개 + 선정 근거
- [ ] 3. 대화 번역 + 원문 뉘앙스 메모
- [ ] 4. 연출 지시 → `references/fun-script-checklist.md` 검사
- [ ] 5. 제목·썸네일 문구·3초 훅 — 확인받기
- [ ] 6. 썸네일 생성 — AI 이미지는 ⛔ 크레딧 승인 후
- [ ] 7. 조립 + 업로드 전 체크 — 실패하면 아래 "돌아갈 단계"대로

## ⚠️ 저작권 원칙 (매 작업마다 확인)

해외 원본을 번역해서 그대로 재업로드하는 것은 저작권 침해 소지가 크다. 다음 원칙을 지킨다:

1. **그대로 번역 재업로드 금지.** 원본 영상을 단순 번역·재인코딩만 해서 올리는 방식은 하지 않는다.
2. **재구성(transformative use)을 반드시 거친다**: 하이라이트만 발췌 + 자체 내레이션/코멘터리 추가 + 자막·그래픽 오버레이 + 편집 재구성. "단순 짜깁기"가 아니라 "새로운 해설 콘텐츠"로 만든다.
3. **출처 표기**를 영상 내/설명란에 명시한다.
4. 뉴스 소스는 팩트 자체(사실관계)는 저작권 대상이 아니지만, 특정 매체의 표현·편집·영상 자체는 보호 대상이 될 수 있음을 인지한다.
5. 특정 채널(레퍼런스)의 영상을 그대로 복제하는 방식이 아니라 **포맷/편집 리듬만 참고**한다.
6. 저작권 판단이 애매한 경우 사용자에게 리스크를 먼저 알리고 진행 여부를 확인받는다. (스킬은 여기서 법률 자문을 제공하지 않으며, 필요 시 사용자가 직접 법률 검토를 받도록 안내한다.)

## 워크플로우 (Phase 0~7)

### Phase 0. 소재 발굴 (해외 영상 후보 매일 5개 선정)

매 작업 시작 시, 아래 기준으로 원본 후보 영상을 찾아 5개를 제시하고 그중 몇 개를 만들지 사용자에게 확인받는다.

**소재 범위**: 특정 국가에 한정하지 않고 전 세계 영상을 대상으로 한다 (미국/유럽/동남아/남미/중동 등 지역 편중 없이 다양하게 섞어서 제시).

**분류 다양화 원칙**: 5개 후보가 서로 겹치지 않도록, 아래 하위 카테고리 중 최소 3개 이상을 섞어서 구성한다.
- 음식(K-푸드 첫 시식) / 언어(한글 배우기) / 전통문화(한복·명절 등) / 현대문화(K-팝·드라마 성지순례 등) / 일상 체험(대중교통·편의점·목욕탕 등) / 여행 브이로그

**우선 선정 기준** (아래 두 유형을 우선하되, 반드시 이 두 유형만 고집하지는 않는다):
- **재미형**: 외국인 출연자의 반응이 재밌거나, 상황 자체가 흥미로운 영상 (챌린지, 예상외 반응, 티키타카 대화 등)
- **한국 체험/발견형**: 외국인이 한국 문화·음식·언어·일상을 처음 접하고 반응하는 영상 (K-푸드 첫 시식, 한국 여행 브이로그, 한글 배우기, 한국 제품 리뷰 등)

**검색 방법**: `WebSearch`로 최근 업로드/화제 영상을 탐색한다. 검색어 예시:
- "foreigners try Korean food reaction"
- "first time in Korea vlog [국가명]"
- "Korean culture shock [언어권]"
- 특정 국가에 치우치지 않도록 국가/언어를 매번 바꿔가며 검색한다.
- `WebSearch`는 실시간 트렌딩/조회수 순위를 제공하지 않는다는 한계를 인지한다. 정확한 조회수 기반 랭킹이 필요하면 YouTube Data API 연동을 사용자에게 별도 제안한다 (이 스킬 범위 밖).

**후보 제시 형식**: 5개 후보를 아래 표로 정리해 확인받는다. **분류가 겹치지 않게, 선정 이유를 구체적으로 남긴다.**

| # | 국가/언어권 | 제목(원문) | 하위분류 | 화제성/검증 지표 | 선정 이유 |
|---|---|---|---|---|---|
| 1 | | | | 검색 결과에 노출된 업로드일·설명 기반 (정확한 조회수는 원문 링크에서 직접 확인 필요) | |

- 화제성 지표는 `WebSearch`로 확인 가능한 범위(업로드 시점, 설명란 언급 등)까지만 표기하고, 실제 조회수·좋아요 수는 "링크에서 직접 확인 필요"로 명시한다. 확인되지 않은 수치를 지어내지 않는다.
- 검색으로 찾은 영상만 후보로 올리고, 실제로 존재하는지 확인 안 된 영상을 지어내지 않는다.
- 사용자가 후보 중 일부를 선택하면 그 영상부터 Phase 1로 진행한다.

### Phase 1. 원본 확보 + 사실관계 정리

- 원본 영상의 발화 내용을 텍스트로 정리(자체 스크립트 확보). 원본 자막 파일을 우선 쓰고, 없으면 Whisper STT를 쓴다 (위 "사용 도구 + 설치").
- 핵심 사실관계(누가, 언제, 무엇을) 목록화 — 이후 재구성 대본의 근거로만 쓰고, 원문 표현을 그대로 베끼지 않는다.

### Phase 2. 하이라이트 구간 선정

다음 기준으로 원본에서 3~5개 후보 구간(각 15~60초)을 고른다:
- **감정 피크**: 놀람/분노/눈물/반전이 드러나는 순간
- **정보 밀도**: 핵심 수치·발언·결정적 한 줄이 나오는 순간
- **비주얼 임팩트**: 표정 클로즈업, 사고/사건 장면, 극적인 제스처

각 후보에 대해 "왜 이 구간이 클릭을 유도하는가"를 한 줄로 근거를 남긴다.

### Phase 3. 대화 번역 (등장인물 톤 살리기)

- 등장인물의 대사를 **뉴스 보도체가 아니라 실제 대화하듯** 자연스러운 구어체 한국어로 옮긴다. 인물의 성격/말투(장난스러움, 진지함, 급함 등)가 드러나도록 어미와 리듬을 살린다.
- 여러 인물이 있으면 화자별로 말투를 구분한다 (예: 캐주얼한 반말/존댓말, 사투리 느낌, 감탄사 사용 여부 등 원본 뉘앙스에 맞게).
- 직역이 어색한 관용구/농담은 한국 시청자가 바로 이해할 수 있는 표현으로 로컬라이징한다. 단, 사실관계나 발언의 핵심 의미는 바꾸지 않는다.
- 번역 대사 옆에 "원문 뉘앙스 메모"를 짧게 남겨, 편집 단계에서 의미가 왜곡되지 않았는지 나중에 대조할 수 있게 한다.

### Phase 4. 하이라이트 연출 강화 (클로즈업 · 비교 · 재미 포인트)

하이라이트 구간마다 아래 연출 요소를 대본에 명시적으로 표시한다:

- **클로즈업 지시**: 표정 변화, 손짓, 반응 순간 등 감정이 드러나는 프레임을 "[클로즈업: ○○의 놀란 표정]"처럼 대본에 컷 지시로 넣는다.
- **비교 연출**: 발언 전/후, 기대와 결과, A안/B안 등을 나란히 보여주는 분할 화면·자막 비교("Before/After", "예상 vs 실제")를 넣을 지점을 표시한다.
- **재미 포인트 강조**: 웃긴 반응, 예상외 전개, 티키타카(주고받는 대화)가 빠른 구간은 자막 크기/이펙트(효과음 자막, 강조 텍스트)를 강조하도록 대본에 별도 표시한다.
- **템포 조절**: 재미있는 구간은 컷 전환을 빠르게, 감정선이 필요한 구간은 살짝 여백(정적)을 두도록 편집 리듬을 대본 옆에 메모한다.

대본 형식 예시:
```
[00:12] 대사(번역): "아니 이걸 지금 알았다고?"
[연출] 클로즈업: 놀라는 표정 0.5초 정지 + 효과음 자막 "헐?!"
[00:15] 대사(번역): "나만 몰랐던 거야 지금?"
[연출] 비교 자막: "예상: 다 알고 있었음" vs "실제: 혼자만 몰랐음"
```

`references/fun-script-checklist.md`로 "재미 포인트가 살아있는 대본"인지 점검한다.

### Phase 5. 클릭 유도 제목 · 썸네일 문구

**원칙**: 사실을 과장·왜곡하지 않는 선에서 궁금증을 극대화한다. 내용과 무관한 낚시성 제목은 채널 신뢰도를 깎고 플랫폼 정책 위반 소지도 있으므로 피한다.

뉴스 보도체가 아니라, **번역된 실제 대사 자체를 재료로** 재미 위주 문장을 뽑는다:
- **대사 직인용형**: 가장 웃기거나 임팩트 있는 번역 대사를 그대로 제목에 노출 (예: 인물이 실제로 한 말 중 임팩트 있는 한 줄)
- **반전형**: "결국 반전은 이거였다" 식으로 Phase 4에서 표시한 비교(예상 vs 실제) 지점을 활용
- **리액션 예고형**: "이 반응 실화냐" 식으로 클로즈업 표정 포인트를 예고
- **상황 요약형**: 무슨 상황인지 한 줄로 궁금하게 요약 (전체 맥락은 숨기고 결정적 장면만 암시)

각 하이라이트 구간마다 제목 후보 3개, 썸네일 문구(1~2단어), 영상 시작 3초 훅 자막을 세트로 제시하고 사용자 확인을 받는다.

### Phase 6. 썸네일 자동 생성

Phase 4의 클로즈업 지시, Phase 5의 썸네일 문구를 재료로 썸네일을 자동 생성한다.

**방식 A — 실제 영상 프레임 활용 (기본, 우선 권장)**
1. 편집본에서 클로즈업 순간의 프레임을 추출한다 (`ffmpeg -ss <시간> -frames:v 1 thumb.jpg`).
2. 추출한 프레임 위에 Phase 5의 썸네일 문구(1~2단어, 큰 글씨)를 오버레이한다. 비교 연출이 있는 클립이면 Before/After 2분할 구도도 고려한다.
3. 실존 인물 프레임을 그대로 쓰는 방식이므로 저작권 원칙(하이라이트 발췌 + 자체 텍스트 오버레이로 재구성)을 그대로 따른다.

**방식 B — AI 이미지 생성 보조 (스타일 커버, 섬네일 배경 등 보조용)**
- 실제 인물 프레임 없이 분위기/배경만 필요한 경우(예: 챌린지형 썸네일 배경, 아이콘형 그래픽) Higgsfield `generate_image`를 쓴다. **생성 전에 장당 차감액과 잔액을 보여주고 멈춰서, 금액 승인을 받은 뒤에만 호출한다.**
- **실존 인물의 얼굴을 AI로 새로 생성해서 원본 인물인 것처럼 쓰지 않는다.** 실제 인물이 나와야 하는 썸네일은 반드시 방식 A(실제 프레임)를 쓴다.
- AI 생성 이미지는 배경·그래픽 요소·텍스트 강조 효과 등 보조 요소에만 한정한다.

**썸네일 구성 체크**
- [ ] 텍스트는 모바일 작은 화면에서도 읽히는 크기인가 (보통 6단어 이내)
- [ ] 클로즈업 표정이 감정을 명확히 전달하는가
- [ ] 제목과 썸네일 문구가 서로 다른 정보를 담아 시너지를 내는가 (썸네일에 제목을 그대로 반복하지 않는다)
- [ ] 실제 영상 내용과 괴리된 과장된 이미지가 아닌가

여러 하이라이트를 제작할 경우, 영상별 썸네일 후보를 나란히 비교표로 제시하고 사용자가 최종 선택하게 한다.

### Phase 7. 조립 + 배포 준비

- 번역 대사 + 클로즈업/비교 연출 지시 + 재미 강조 자막 + 출처 표기를 CapCut 등으로 조립.
- 업로드 전 체크리스트: 저작권 원칙 재확인, 번역이 원문 의미를 왜곡하지 않았는지, 자막 오탈자, 출처 표기 여부.
- 돌아갈 단계: 번역 왜곡·오탈자 → Phase 3 / 재미 포인트·연출 부족 → Phase 4 / 제목·썸네일이 내용과 안 맞음 → Phase 5 / 재구성이 부족해 저작권 리스크 → Phase 2 (구간 다시 고르기)

## 검사 → 고치기 → 반복

- 검사 기준: `references/fun-script-checklist.md` (대본), 위 업로드 전 체크리스트 (최종본).
- 미통과 항목은 "돌아갈 단계"대로 고치고 다시 검사한다. 전부 통과해야 끝이다.
- 기준 문서에 없는 이유로 걸렸다면, 작업 끝에 fun-script-checklist.md에 넣을 새 규칙 1개를 제안하고 사용자 승인을 받는다.
- 여러 언어 버전 제작 시 언어별 파일/제목/설명란을 세트로 정리해 보고한다.
