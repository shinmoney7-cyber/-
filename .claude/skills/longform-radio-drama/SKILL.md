# 롱폼 라디오 드라마 — 수익 포함 통합 제작 스킬

## 사용 도구 + 설치

- `scripts/count_chars.py`, `scripts/make_srt.py` — python3만 있으면 됨 (추가 설치 없음)
- Higgsfield MCP (`generate_image`, `generate_video`, `generate_audio`, `balance`, `models_explore`) — deferred면 ToolSearch로 로드, 없으면 claude.ai 설정 > 커넥터에서 Higgsfield 연결 안내
- Vrew (vrew.ai), CapCut (capcut.com) — 사용자 PC에 설치하는 데스크톱 앱

## 참고 파일

## Phase 2. HERO 구조 대본 (60분 = 약 30,000자)

### 분량 기준표

| 구간 | 시간 | 자수 목표 | 핵심 목적 |
|------|------|---------|---------|
| 🎣 HOOK | 20초 | 150~200자 | 클라이맥스 선공개, 이탈 방지 |
| ACT 1 | 0~15분 | 7,500자 | 일상 설정 + 복선 2~3개 |
| ACT 2 | 15~30분 | 7,500자 | 균열 + 의심 사이클 |
| ACT 3 | 30~45분 | 7,500자 | 클라이맥스 + 반전 투하 |
| ACT 4 | 45~57분 | 6,000자 | 선택 + 변화 + 여운 |
| OUTRO | 57~60분 | 1,500자 | DJ 멘트 + CTA |
| **합계** | **60분** | **~30,150자** | |

> 낭독 속도 기준 500자/분 (Vrew TTS 속도 0.95배)

### 작성 방법

- 대본은 구간마다 `## HOOK`, `## ACT 1` ~ `## ACT 4`, `## OUTRO` 제목 줄을 붙여 쓴다 (자수 검사 스크립트가 이 제목으로 구간을 나눈다).
- 30,000자를 한 번에 쓰지 않는다. HOOK+ACT 1 → ACT 2 → ACT 3 → ACT 4+OUTRO 순서로 나눠 쓰고, 앞 구간의 복선 목록을 다음 구간으로 넘긴다.
- 다 쓰면 파일로 저장하고 자수를 검사한다:
  ```bash
  python3 scripts/count_chars.py 대본.txt
  ```
  ❌ 구간이 있으면 그 구간을 보강하고 다시 검사한다. 모두 ✅여야 Phase 3으로 간다.

## Phase 4. Higgsfield 이미지 & 영상 제작 ⛔ 크레딧 승인 게이트

생성 전에 반드시 이 순서를 지킨다:
1. 아래 표의 모델이 지금도 있는지 `models_explore`로 확인한다 (모델 이름·크레딧은 바뀔 수 있다).
2. 만들 장수·클립 수로 예상 차감액을 계산하고, `balance`로 잔액을 확인한다.
3. "총 N크레딧 차감 / 현재 잔액 M / 절약안(이미지+켄번즈) N크레딧"을 보여주고 멈춘다.
4. 금액 승인을 받은 뒤에만 생성 도구를 호출한다. 다른 단계의 확인은 금액 승인이 아니다.

### 도구별 용도 + 크레딧

| 용도 | 모델 | 크레딧 | 비고 |
|------|------|--------|------|
| 썸네일 | nano_banana_2 | ~2/장 | 충격적 표정·장면 |
| 배경 이미지 | seedream_v4_5 | ~3/장 | 감정 분위기별 |
| 영상 클립 | Seedance 2.0 | ~67/클립 | 5~10초 |

## Phase 6. SRT 자막 파일

### 포맷 규칙

```
[표준 블록]
1
00:00:00,000 --> 00:00:03,500
그날따라 유난히 바람이 찼습니다.

2
00:00:03,500 --> 00:00:07,000
[BGM이 잔잔하게 깔리기 시작합니다]

규칙:
• 1블록 = 최대 2줄 / 1줄 = 최대 15자
• 60분 기준 총 900~1,100블록
• 음악 큐: [BGM: 긴장감 있는 음악], [BGM 멈춤]
• 대량 생성 시: 10분 단위로 나눠 생성 후 번호 이어붙이기
```

### 만드는 방법 (손으로 번호·시간을 매기지 않는다)

```bash
python3 scripts/make_srt.py 대본.txt 자막.srt --cpm 500 --pause 0.5
```

- 1줄 15자 / 1블록 2줄 / 시간 계산 / 번호 매기기를 스크립트가 한다. 채널별 속도가 다르면 `--cpm`을 바꾼다 (0.90배 ≈ 475, 1.00배 ≈ 525).
- 블록 수가 900~1,100개 범위를 크게 벗어나면 대본 분량부터 다시 확인한다 (Phase 2로).
- 이 파일은 초안이다. 실제 음성과 맞춘 최종 자막은 Vrew에서 TTS 생성 후 내보낸 SRT를 쓴다.

## 검사 → 고치기 → 반복

- 검사 기준: Phase 2 "대본 핵심 규칙", 분량 기준표(`scripts/count_chars.py`), Phase 6 SRT 규칙(`scripts/make_srt.py` 블록 수).
- 돌아갈 단계: 자수 미달·규칙 위반 → Phase 2 / SRT 블록 수 이상 → Phase 2 / TTS와 자막이 안 맞음 → Phase 3에서 Vrew SRT를 다시 내보내기 / 이미지가 분위기와 안 맞음 → Phase 4 (크레딧 승인 다시)
- 고치고 다시 검사한다. 전부 통과해야 끝이다.
- 기준에 없는 이유로 걸렸다면, 작업 끝에 새 규칙 1개를 제안하고 사용자 승인을 받는다.
